# Self-Study Operating System

Use this academy as a controlled path, not as a reading list.

For each phase:

1. Learn the native lesson.
2. Predict behavior before running commands or workflows.
3. Build in your own implementation repository.
4. Use the matching lab in `LAB_MAP.md`.
5. Break or inject failure deliberately.
6. Run the provided checks/evaluator where one exists.
7. Explain what failed and why.
8. Pass the phase assessment before advancing.

## When you are stuck

Use this order:

1. inspect logs/state/input/output,
2. reread the relevant academy section,
3. use the lab README hints,
4. consult official documentation,
5. only then search more broadly.

The goal is to prevent tutorial hopping while still teaching you how to use documentation like an engineer.

## What counts as mastery

A lesson is not complete because it was read. A capability is complete when you can build it, diagnose a realistic failure, explain the trade-offs, and reproduce the result from a clean environment.

Keep personal progress outside this canonical repository using `PROGRESS_TEMPLATE.md`.

# Module 0.1 — What Automation Actually Is

## Goal
Learn to see automation as a system, not a collection of app integrations.

## Mental model
A useful automation has:

**Trigger → Inputs → Decisions → Actions/Transformations → Outputs → State → Exceptions → Human handoffs**

The tool is secondary. The process comes first.

## Example
"When a lead submits a form, send an email" is a tiny workflow.

A real lead system may also need:
- duplicate detection
- enrichment
- validation
- routing rules
- CRM state
- retries
- notification failure handling
- human approval for unusual cases
- audit history

## Exercise
Take three repetitive activities from daily life or a fictional business. For each, map the eight elements above.

## Checkpoint
Explain why automating a badly understood process can make the business worse faster.

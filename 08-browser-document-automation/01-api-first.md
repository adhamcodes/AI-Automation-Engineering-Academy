# Module 08.1 — API-First vs Browser Automation

## Capability
Choose browser automation only when an API/integration is unavailable or insufficient.

## Core model
Browser automation depends on UI structure and is usually more fragile than supported APIs. Compare permissions, reliability, legal/ToS constraints and maintenance cost first.

## Practice
For five tasks, find API/integration options before proposing browser control.

## Failure / transfer task
Replace a brittle scrape with documented endpoint where possible.

## Evidence to save
Decision record showing why browser automation is justified.

## Mastery
You can defend maintenance/legal risk.

# How to Use This Academy

## The rule that matters most
Advance by **capability**, not by content consumption.

## Normal module workflow

1. Read the process/capability goal.
2. Study the assigned primary material.
3. Build the smallest working version.
4. Test bad input and failure paths.
5. Add state/recovery/observability when the phase requires them.
6. Complete the debugging/transfer task.
7. Save evidence: workflow/code, test cases, architecture notes, and handover notes.
8. Pass the phase/commercial gate before claiming the capability.

## Time
The roadmap assumes roughly 2–3 focused hours/day for planning purposes, but progression is mastery-based. Faster is fine when the gate is genuinely passed; slower is fine when a prerequisite needs repair.

## AI assistance
AI can accelerate exploration and debugging where allowed, but you remain responsible for credentials, permissions, data handling, architecture, testing, and the actual behavior of the system. Closed assessments must be attempted under their stated rules.

## Working with another learner
Build core exercises independently, then compare system diagrams, error handling, data models, logs, and tradeoffs. Reviewing two different valid implementations is more useful than sharing one answer.

## Commercial simulations
Treat simulations as engineering work: write assumptions, acceptance criteria, security boundaries, ownership, failure modes, and handover. Never fabricate a real client result.

## When you get stuck
Reduce the workflow to one trigger + one action, inspect raw inputs/outputs, reproduce the failure, read the API/platform docs, and only then add complexity back.

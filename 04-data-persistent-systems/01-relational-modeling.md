# Module 04.1 — Relational Data Modeling

## Capability
Turn workflow entities and relationships into a stable schema.

## Core model
Tables model entity types; primary keys identify rows; foreign keys express relationships; constraints protect invariants. Schema design should reflect business identity, not spreadsheet layout.

## Practice
Model customers, leads, workflow runs and actions with keys/constraints.

## Failure / debugging task
Find duplicate identity caused by using email/name as an unstable primary key.

## Evidence to save
ER-style diagram + SQL schema.

## Mastery
You can explain each table/key/constraint in business terms.

# Monetization Playbook

Monetization begins when capability supports it—not when a calendar says “Month 3.”

## Stage A — Proof before selling
Build 3–5 demonstrators that show different capabilities: API integration, database-backed workflow, AI-assisted workflow with human review, and a reliability-focused system. Record architecture, failure cases, and a short demo.

## Stage B — Problem discovery
Look for repetitive processes with measurable friction: copying data, lead routing, onboarding, report generation, support triage, document handling, notifications, approvals, and system synchronization. Avoid selling “AI automation” as an abstract product.

## Stage C — Low-risk market tests
Possible channels include direct businesses, agencies that need implementation capacity, job/contract applications, productized services, communities, content/case studies, and later reusable templates/products. Marketplace freelancing is optional, not mandatory.

## Stage D — Scope before price
Write current process, desired outcome, systems/accounts involved, data sensitivity, error cases, human approvals, volume, ownership/hosting, acceptance criteria, and support boundary before quoting.

## Stage E — Deliver professionally
Use versioned workflows/code, secrets management, test cases, rollback/backup, runbook, handover documentation, and explicit maintenance terms.

## Stage F — Productize only after repetition
When the same problem and architecture repeat across multiple users, extract reusable components. Do not turn the first custom workflow into a SaaS because it feels scalable.
